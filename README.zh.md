# dsh-capability-panel

[English](README.md) | 中文

DeepSeek Harness 的技能与工具控制面：既能看清并临时调整当前会话，也能持久微调每个 Agent preset 的默认工具集合。

---

## 它解决什么问题

技能"装好了"和技能"此刻在模型的上下文里"是两件事，而只有后者能回答"为什么 agent 不知道这个"。压缩（compaction）会把一段历史替换成一条摘要，于是一个早先加载过的技能，它的加载记录永久留在日志里，却已经从模型的视野里消失了。

同样，你可能想在某一次对话里临时不让模型碰某个工具——不是卸载插件，不是改配置文件重启，就只是这一个会话、从下一步开始。

本插件把这两件事做成对话框右下角一个面板。

## 功能

- **三个分区**：技能、MCP、系统工具，各自显示总数
- **加载状态**：每个技能标为 `已加载`（还在上下文里）/ `已截断`（首尾还在，中间被剪枝截断）/ `已挤出`（被压缩掉了）/ `未加载`，并显示累计加载次数——被挤出后又重新加载的技能读作"已加载，加载 2 次"
- **按会话开关**：关掉某个技能或工具后，从下一步的提示组装起模型就看不到它，而已有的对话历史、已加载的指令内容都不动
- **Preset 默认值**：在「设置 → Agent Toolkit」中持久保存每个 Agent preset 的工具开关；之后新建或恢复的会话会继承它，输入框里的「会话上下文」仍然只改当前会话。筛选、分组、开关都与会话面板一致——MCP 工具折叠在所属服务器下，服务器一次开关即可覆盖其全部工具
- **MCP 按服务器分组**：既能关单个工具，也能一次关掉整个服务器
- **拦截统计**：关掉之后模型还硬着头皮调用的次数。非零意味着模型凭记忆行动，是"这个开关需不需要更明确地告知模型"的信号
- **一键填充命令**：点技能行的按钮，把 `/技能名` 填进输入框
- **筛选**：按名称或描述过滤，筛选时自动展开匹配项的描述
- **跟随界面语言**：面板文案随宿主语言设置在中英之间切换

## 安装

```bash
dsh plugin --profile web add dsh-capability-panel
```

安装后需要重启 dsh 才生效。

## 使用

打开任意对话，点输入框右侧那个图层图标（28×28，靠右），面板从上方弹出。

- 顶部三个选项卡：**技能 N** / **MCP N** / **工具 N**
- 每一行右侧是开关；点开关即刻生效，无需刷新
- 点行本身展开描述
- 顶部筛选框按名称或描述过滤，匹配数 `匹配 X / Y 项` 显示在框下方
- 关掉的项目会以更淡的样式显示，并在模型的系统提示里生成一条说明（"用户关闭了以下能力，不要尝试调用"）

`run_code` 是 Code Mode 的保留传输通道，注册表禁止遮蔽它，所以它的开关不可操作。

同一组开关存在于两个作用域：输入框里的**会话上下文**只改眼前这轮对话（重启后随该会话恢复），**设置 → Agent Toolkit** 则决定之后每个会话从什么状态开始。要修改持久默认值，打开设置 → Agent Toolkit，选择一个 preset 后开关工具。一个 preset 可能暴露上百个工具，因此这里同样带筛选框，并把每个 MCP 服务器折叠成一行，用一个开关覆盖它的所有工具。设置会在会话 agent 创建时读取（包括恢复的会话），不会改写 preset 文件，也不会改变已经运行的 agent。

## 工作原理

**加载状态直接读 live session 的内存表面，而不是每次从日志折叠。** 面板借用正在运行的会话自身的视图——`session.snapshotEvents()` 拿事件引用、`session.surface.nodes` 拿增量维护的"下一次请求模型可见"的序号集合——一次读取就是一次零拷贝扫描，没有日志克隆、没有回放校验、也没有跨读竞态。（此前走 `sessionQuery.readSession`/`listEvents`，每次打开面板最多把整条日志克隆并重新校验两遍，长会话上会冻结宿主进程。）技能的状态仍然由它那次 `skill` 调用**配对的工具结果**决定——而不是调用本身，因为压缩后高序号的摘要节点会占据被遮蔽区间的**位置**，表面顺序不再跟随序号顺序，用 `start <= seq <= end` 的数值判断会误判后续的压缩。状态区分三种结果：`loaded`（完整结果在表面上）、`pruned`（工具结果剪枝器在表面上留下了"头+标记+尾"的截断桩——模型还能看到首尾）、`evicted`（结果被压缩整体遮蔽）。持久化日志完全不被触碰；这些状态描述的是模型的当前视野，不是存档。

**开关分两层。** 全局工具走 `tools.restrict`，在注册表层遮蔽，dispatch 直接报 `UNKNOWN_TOOL`。preset 层的系统工具 `restrict` 遮不住，所以走两条路：`system-prompt/assemble` 事件在每次组装时摘掉它的 schema（模型看不见，也不占上下文），`tools.guard` 兜底拦执行（模型凭记忆硬调时被拒绝）。两者都注册在 host 层、按 agent id 精确命中，不影响其他会话。

**技能的开关是同名遮蔽。** 在该 agent 自己的作用域层注册一个同名、`modelInvocable: false` 的技能。分层注册表让最近的作用域赢得这个名字，于是模型面向的目录和 `skill` 加载器都不再提供它，而 `/名字` 这种用户主动调用仍然可用。重新打开就是销毁这个遮蔽，原技能自动重新胜出。

**会话开关按会话绑定并持久化，但绝不写进对话日志。** 每次切换都记录在插件设置命名空间下、以会话自己的 id 为键，所以恢复会话（重启后新建的 agent）会在 preset 默认值之上还原这个会话自己的开关——而一个会话的开关绝不会串到另一个会话。对话历史本身不受影响：遮罩是每次组装时的覆盖层，"这些已关闭"的提示也在组装时现算，日志里不会留下任何过时残留。Preset 默认值仍然是每个**新**会话的初始层。

**统计不参与控制流。** 拦截计数写在 JSONL 追加日志里，启动时重放恢复；任何 I/O 失败都被吞掉，绝不阻断开关本身。

## 数据存放

- Preset 默认值与会话绑定的开关位置：`$DSH_HOME/settings.yaml` 的 `capability-panel` 命名空间（会话开关在 `sessions.<sessionId>` 下，最多保留 200 个会话、最旧的先淘汰；宿主从不丢弃未加载插件的分节，所以卸载后它们还在，直到你手动删除该段）
- 拦截统计：`$DSH_HOME/capability-panel/stats.jsonl`
- 原始统计可直接读取：`curl 'http://127.0.0.1:3080/api/capability-panel/stats'`

数据路由只接受 loopback 请求：判定依据是连接对端地址，Host / Origin 头只在 socket 不可用时回落，两者都没有时拒绝。

## 开发

```bash
pnpm install
pnpm dev        # 监听构建
pnpm build      # 构建 host + client 两半
pnpm test       # 运行测试
pnpm typecheck  # 类型检查
pnpm lint       # oxlint（含类型感知规则）
pnpm check      # typecheck + lint + test
```

改动 host 半需要重启 dsh；client 半在 `dsh web` 与 watch 同时运行时热替换。
